# Genre replacement implementation plan

> Execute inline using executing-plans and test-driven-development. User approved replacing played_at with genre when they share the same core logic.

**Goal:** Replace the timestamp with a free-text genre, without adding recommendation or aggregation features.

**Architecture:** Keep SQL -> engine -> fixed-record storage. Genre is printable ASCII, 1..31 bytes, case-sensitive, no fixed whitelist. SQL_GENRE replaces SQL_PLAYED_AT. Version 2 has 92-byte records: id/user/song at 0/8/16, event_code[32] at 24, genre[32] at 56, checksum at 88. Header magic stays MJDBMS1, version becomes 2, record_size becomes 92. Default path becomes data/play_history_v2.db; previous v1 files are preserved and rejected, never interpreted as genres.

**Tech stack:** C11, GCC, Python unittest, Ubuntu Docker.
