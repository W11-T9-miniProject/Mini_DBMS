# 음악 재생 이력 Phase 1 — SQL 처리·실행·CLI

사용자 승인: C, play_history 고정 스키마, 바이너리 저장을 유지하고 다음 SQL 처리 단계 진행.

## 문법

INSERT INTO play_history (event_code,user_id,song_id,genre) VALUES ('PLAY000001',71,305,'rock');
SELECT * FROM play_history;
SELECT * FROM play_history WHERE id = 1;
SELECT * FROM play_history WHERE user_id = 71;
SELECT * FROM play_history WHERE event_code = 'PLAY000001';

키워드·테이블·열 이름은 ASCII 대소문자 무시. 문자열 값은 보존한다.
INSERT는 네 입력 열을 각각 정확히 한 번 명시한다. 순서는 바꿀 수 있다. id는 자동 부여한다.
SELECT는 *와 선택적인 단일 등호 WHERE를 지원한다. 다섯 열 모두 조건으로 사용 가능하다. 숫자 열은 부호 없는 64비트 정수, 문자열 열은 작은따옴표 문자열이다.
여러 문장은 세미콜론으로 구분한다. 마지막 세미콜론은 생략할 수 있다. -- 줄 주석, 공백, 여러 줄 문장을 지원한다. 문자열 내부의 세미콜론·--는 값이다. 작은따옴표 두 개('')는 값의 작은따옴표 하나다. 백슬래시는 이스케이프 문법이 아니다.
CREATE/UPDATE/DELETE/JOIN/AND/OR/ORDER BY/열 선택/범위 조건/블록 주석은 지원하지 않고 오류다.
파서는 입력 문장을 독립된 구조체로 복사하고 파일을 변경하지 않는다. 양의 ID/비어 있지 않은 ASCII 문자열 등 레코드 의미 검사는 저장 계층에서 수행한다.

## 구성

include/sql.h + src/sql.c: 메모리 SQL 스크립트의 토큰화/구문 분석. sql_parser_init와 sql_next. 오류 위치·메시지 반환. 긴 식별자·문자열·숫자 넘침·NUL은 거절. 실패하면 결과 구조체를 변경하지 않고 파서를 중지한다.
include/engine.h + src/engine.c: db_file을 소유하는 내부 엔진. INSERT는 저장 모듈 호출, SELECT는 파일의 레코드를 순서대로 읽고 필터링. 결과는 콜백으로 전달해 100만 행 결과를 메모리에 모으지 않는다. 인덱스 없는 현재 경로는 ID 조건도 선형 탐색한다.
src/main.c: mini-dbms [--db path] sql-file. 기본 data/play_history_v2.db. SQL 파일은 최대256MiB 메모리에 읽는다. 결과 행·SELECT 집계·최종 요약은 JSON Lines로 출력한다.

SQL 파일은 문장 단위로 실행하며 처음 오류에서 중지한다. 앞선 성공 INSERT는 남을 수 있다. 전체 파일은 트랜잭션이 아니다. 정상/실패 모두 엔진 close에서 기존 성공 쓰기를 동기화한다. 최종 status=ok는 close 성공 이후 출력한다. SELECT 행 출력은 최종 요약 전 나타날 수 있다.
Phase 2 데이터 생성 시 이 파일 크기 상한을 고려하거나 문장별 엔진 호출/여러 SQL 파일로 나눌 수 있다. 파일 로딩 비용과 시작 검증 비용은 검색 시간과 구분한다.
동시 스레드 사용은 Phase3에서 엔진+파일+인덱스 전체를 보호하도록 설계한다.
