# 음악 재생 이력 DBMS — 파일 저장 모듈 설계

사용자가 승인한 방향: C, Redis와 독립된 프로젝트, 음악 재생 사건을 한 행으로 관리, 고정 길이 바이너리. 첫 구현은 SQL 연결 전 저장·재읽기 검증이었다. 2026-11-16에 사용자 결정으로 재생 시각을 장르로 교체한 현재 규칙을 반영했다.

## 전체 단계

Phase 1: SQL 파일 → CLI → 파서 → 실행기 → 테이블 파일.
Phase 2: 같은 실행기에 메모리 B+ 트리(ID → 파일 오프셋)와 100만 건 비교 추가.
Phase 3: 같은 엔진을 API와 작업 큐·워커 스레드 풀에서 호출.

현재 Phase 1은 CLI·SQL 파서·실행기를 포함한다. 이 문서는 파일 저장 계층을 설명한다. Phase 2에서 메모리 B+ 트리를 연결했다. Phase 3에서 HTTP API와 스레드 풀도 연결했다.

## 레코드

id: 자동 증가 64비트 양의 정수, 첫 값 1.
event_code: ASCII 출력 문자 1~31바이트. 중복은 허용한다. 성능 실험에서는 생성기가 중복 없는 값을 만든다.
user_id, song_id: 64비트 양의 정수.
genre: ASCII 출력 문자 1~31바이트. 고정 장르 목록 없이 저장하고 대소문자를 구분한다. 빈 값·제어 문자·길이 초과는 거절한다.

## 파일 형식 v2

32바이트 헤더: magic 8바이트 MJDBMS1\0, version u32LE(2), record_size u32LE(92), 예약 영역 12바이트(0), 앞 28바이트의 FNV-1a32 체크섬.
92바이트 레코드: id u64LE(0), user_id u64LE(8), song_id u64LE(16), event_code 32바이트(24), genre 32바이트(56), 앞 88바이트의 FNV-1a32 체크섬(88).
문자열은 NUL 종료 후 남은 바이트를 0으로 채운다. C 구조체의 원시 바이트를 파일에 쓰지 않는다.
헤더에는 변경 가능한 행 수를 저장하지 않는다. 열 때 파일 크기와 모든 레코드·ID 순서를 검증하고 행 수를 재구성한다.

## 인터페이스와 오류

불투명 db_file 핸들. db_open/create, db_append(입력 id는 0), db_read_at(바이트 오프셋), db_count, db_sync, db_close.
append는 저장된 레코드와 파일 오프셋을 돌려준다. Phase 1은 오프셋을 차례로 읽고, Phase 2는 B+ 트리에 같은 오프셋을 등록한다.
프로세스 간 중복 열기는 배타적 파일 락으로 차단한다. Phase 3에서는 엔진 읽기·쓰기 락이 파일과 인덱스 작업을 함께 보호한다. 저장소의 실패 플래그는 atomic이지만, storage API 자체를 엔진 없이 병렬 호출하는 것은 지원하지 않는다.
잘못된 입력은 파일을 변경하지 않는다. 부분 레코드·체크섬 오류·잘못된 헤더는 자동 삭제·잘라내기 없이 열기를 거절한다.
쓰기/동기화 오류 이후에는 핸들의 추가 쓰기를 차단한다. 기존 정상 행 조회는 가능하다. 부분 쓰기의 성공/실패 결과를 복구할 WAL은 이번 단계에 없다.
append 성공은 운영체제로의 쓰기 완료를 뜻한다. db_sync/db_close 성공 시 fsync가 완료된다. 각 행마다 fsync하지 않으며, SQL 파일 처리 끝의 명시적 동기화/배치 정책은 이후 연결한다. DBMS 전체의 트랜잭션·원자적 배치·전원 장애 복구를 보장하지 않는다.

## 검증

빈 파일, 첫 저장/조회, 재열기 뒤 ID 증가, 정확한 바이트 오프셋, 경계 입력, 장르 문자열 왕복·길이·제어 문자, 잘못된 파일/잘린 꼬리 거절 및 원본 보존, 배타적 열기, 메모리 할당·부분 쓰기·fsync 실패, 1000행 왕복, 별도 프로세스의 저장/조회, ASan/UBSan.

## 환경

Ubuntu 22.04 개발 컨테이너, GCC C11, make, Python3(통합 테스트). 기록용 data/와 build/는 Git에서 제외한다. Mini_Redis 코드는 변경하지 않는다.

기본 데이터 경로는 data/play_history_v2.db. 이전 v1 데이터는 보존하며 자동 변환하지 않고 열기를 거절한다. 장르를 추정하거나 날짜 문자열을 장르로 재해석하지 않는다.
