# Phase 3 — HTTP API and explicit thread pool

User-approved architecture: keep Phase 1/2 engine; HTTP API -> bounded queue -> reusable pthread workers -> shared engine. Concurrent SELECTs use Linux writer-preference nonrecursive reader lock; INSERT holds writer lock across file/index update and fsync before success. Server opens/rebuilds engine once and closes only after workers finish. Storage error flag must be atomic because concurrent read failures can mark it.

Minimal interface: POST /sql, Content-Type: text/plain or application/sql, body is exactly one SQL statement. GET /health returns status and worker/queue counts. No browser UI, auth, TLS, transactions, DELETE/UPDATE, or recommendation features. Bind defaults to 127.0.0.1; explicit --host 0.0.0.0 for remote access on trusted networks. One HTTP request per connection; Connection: close. HTTP syntax parsed by vendored pinned picohttpparser (MIT); framing validation remains ours. Require single Content-Length for POST; reject Transfer-Encoding, Expect and already-arrived extra pipelined bytes. Header <=8KiB, SQL <=16KiB, SELECT output <=1000 rows. Response is one bounded JSON document with rows and execution counts/access path. Row overflow is explicit 413, not partial success.

Pool: configurable 1..32 workers (default4), pending socket capacity1..1024 (default64). Each connection has an absolute5s read deadline and bounded send timeout. Queue full gets503 without SQL execution. Worker reads/parses/executes/builds reply; network send occurs after engine lock release. Request body is parsed completely and checked for a second statement before execution, so multi-statement API requests never partially insert. Disconnect after write may leave committed data: no exactly-once/idempotency claim.

Errors: 400 invalid HTTP/SQL syntax/multiple statements, 404 route, 405 method, 411 missing length, 413 limits, 415 media, 422 invalid record values, 500 engine/memory/I/O, 503 queue full. Missing SELECT results are200. Error JSON strings are escaped. Responses identify worker_id to demonstrate scheduling, not pthread internals. Health is handled by workers like other requests.

Shutdown: SIGINT/SIGTERM set stop flag, main stops accepting, closes pending sockets, lets active requests finish within request limits, joins workers and closes/syncs engine. No thread cancellation. Accepted fd ownership transfers to queue only on submit success. A poll timeout lets signal handling wake the listener; handler does not close fd shared with other threads.

Tests: reader overlap + writer exclusion, concurrent INSERT/SELECT with contiguous unique IDs and index consistency after reopen; HTTP basic/index/fullscan/missing, input/framing/size/multi-statement errors, aborted/fragmented requests, parallel clients, queue saturation/recovery, shutdown/restart. Ordinary and ASan/UBSan suites use temporary DBs. Phase2 benchmark remains batched fsync at close; server uses per-INSERT sync under writer lock.

Validation completed: core43 + HTTP11 =54 groups/cases in normal and ASan/UBSan builds, plus Windows host API smoke via temporary port. Core concurrency includes reader overlap and writer exclusion; pool lifecycle failure tests cover allocation and partial pthread creation cleanup. INSERT response-after-fsync tested by injection and SIGKILL/reopen. Independent review framing issue fixed with bounded enlarged recv + peek and red/green regression. Shutdown waits for active SQL/storage operations; the network deadlines do not cancel an engine operation. No TSan or long-running load test claimed.
