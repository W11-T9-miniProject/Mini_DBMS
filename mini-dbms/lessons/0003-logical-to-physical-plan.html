계획을 실제로
실행하기

논리 계획의 작업을 저장소에서 수행하는 구체적인 방법, 즉 물리 실행을 살펴봅니다.

논리 계획은 “무엇을”, 물리 계획은 “어떻게”

앞 수업의 조회는 논리적으로 다음 작업이었죠.

Project[name]
└── Filter[age >= 18]
    └── Scan[people]

Scan[people]을 실제로 수행하는 방법은 여러 가지일 수 있습니다.

순차 스캔 (Seq Scan)
파일의 첫 행부터 끝까지 차례로 읽는다.

인덱스 스캔 (Index Scan)
인덱스에서 조건에 맞는 행 위치를 찾은 뒤 해당 행을 읽는다.

두 방식은 같은 결과를 만들 수 있지만, 읽는 데이터의 양과 접근 방식이 다릅니다.

현재 프로젝트는 순차 스캔

select_rows()는 people.rows 파일을 열고, db_read()로 행을 하나씩 읽습니다. 각 행은 matches()에서 필터링되고, 조건을 통과한 행에서 요청된 컬럼만 출력됩니다.

파일 열기
  ↓
db_read() ── 다음 행 읽기
  ↓
matches() ── age >= 18 인가?
  ├─ 아니오: 버림
  └─ 예: name 컬럼 출력
  ↓
파일 끝까지 반복

이것은 물리 실행이에요. “테이블을 읽는다”는 논리 작업을 “파일을 앞에서부터 한 행ずつ 읽는다”는 구체적 방법으로 수행합니다.

인덱스가 있으면 언제나 빠를까?

아니에요. 조건에 맞는 행이 아주 많다면 인덱스로 여기저기 이동하며 행을 읽는 것보다 파일을 한 번 쭉 읽는 편이 더 쌀 수 있어요. 그래서 DBMS는 테이블 크기, 인덱스, 값 분포 같은 정보를 이용해 실행 방법을 추정합니다. SQLite의 쿼리 계획 문서는 인덱스를 이용한 검색과 정렬 사례를 보여 줍니다.

현재 미니 DBMS에는 인덱스와 비용 기반 최적화기가 없어서 선택지가 하나뿐입니다. 항상 순차 스캔을 합니다.
