AST를 논리 계획으로
한 단계씩 변환

SELECT AST의 각 정보를 관계 연산자로 옮겨 논리 계획 트리를 만듭니다.

입력: SQL AST

앞 수업의 SelectStmt가 다음 정보를 가지고 있다고 합시다.

SelectStmt {
  table_name: "people",
  projection: [name],
  where: age >= 18
}

1. 테이블부터 Scan으로

FROM people는 어떤 테이블의 행이 필요한지를 말합니다. 그래서 첫 계획 노드는 Scan(people)입니다.

Scan[people]

2. WHERE를 Filter로 감싸기

AST에 WHERE 조건이 있다면, 스캔 결과를 입력으로 받는 Filter 노드를 위에 둡니다.

Filter[age >= 18]
└── Scan[people]

조건 자체는 기존 Expr 트리를 Filter의 조건으로 재사용할 수 있습니다. 지금 프로젝트는 아직 이런 계획 노드를 생성하지 않습니다.

3. SELECT 컬럼을 Project로

마지막으로 SELECT 목록을 Project로 옮겨 결과에 남길 컬럼을 지정합니다.

Project[name]
└── Filter[age >= 18]
    └── Scan[people]

트리는 아래에서 위로 행을 전달합니다. Scan이 행을 만들고, Filter가 일부를 버리고, Project가 컬럼을 줄입니다.

변환 규칙

FROM table → Scan(table)

WHERE predicate가 있으면 → Filter(predicate, child)

SELECT columns → Project(columns, child)

즉 변환기는 AST 필드를 하나씩 읽어 계획 노드를 조립합니다. 계획 생성 단계에서 스키마를 참조해 테이블·컬럼 이름을 내부 컬럼 번호로 바꾸고 타입을 확인할 수도 있습니다.

이건 물리 실행 계획이 아님

Scan[people]은 “people을 읽어라”는 논리 작업입니다. 파일을 처음부터 읽을지, B+트리 인덱스를 사용할지는 다음 단계인 최적화·물리 계획에서 정합니다.

AST → 논리 계획
Project → Filter → Scan
             ↓
최적화 후 물리 선택
Project → Filter → SeqScan(.rows)
       또는 IndexScan(age 인덱스)

이 프로젝트에는 AST 전체도, 논리 계획도, 최적화기도 아직 코드로 존재하지 않습니다. 위는 실제로 구현할 때의 설계 모델입니다.
