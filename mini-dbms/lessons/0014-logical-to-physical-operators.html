논리 계획을
실행 방법으로 바꾸기

논리 계획이 말하는 작업을 저장 계층이 실제로 수행할 수 있는 물리 연산자로 구체화합니다.

입력: 논리 계획

Project[name]
└── Filter[age >= 18]
    └── Scan[people]

이 계획은 결과의 의미를 표현하지만, 아직 어떤 파일·인덱스를 어떻게 읽을지는 정하지 않았습니다.

Scan을 구체적인 방법으로 바꾸기

SeqScan(people) — 테이블 파일을 처음부터 차례로 읽는다.

IndexScan(age_idx) — age 인덱스에서 조건 범위를 찾고 관련 행을 가져온다.

두 물리 계획 모두 같은 논리 작업을 구현할 수 있어요.

Project[name]                    Project[name]
└── Filter[age >= 18]            └── Filter[age >= 18]
    └── SeqScan[people.rows]          └── IndexScan[age_idx]

최적화기가 고르는 지점

최적화기는 테이블 크기, 인덱스 존재 여부, 조건이 남길 행 수 추정 등을 사용해 후보 비용을 비교합니다. 조건에 맞는 행이 적으면 인덱스가 이길 수 있고, 거의 모든 행이 필요하면 순차 스캔이 이길 수 있습니다.

실행기는 선택된 노드들을 실제로 수행합니다. 예를 들어 SeqScan.next()는 다음 행을 읽고, Filter.next()는 조건을 통과한 행이 나올 때까지 입력에서 행을 요청하며, Project.next()는 필요한 컬럼만 내보낼 수 있습니다.

현재 코드에서 대응되는 부분

현재 select_rows()의 행 읽기 반복문은 사실상 SeqScan 동작입니다. db_read()가 다음 행을 읽고, matches()가 Filter 역할을 하며, projection 배열과 출력 코드가 Project 역할을 합니다.

select_rows() 반복문
  db_read()                   ≈ SeqScan에서 다음 행
  matches()                   ≈ Filter
  projection[i] 출력          ≈ Project

다만 이들은 독립 실행 연산자 객체로 나뉘지 않고, 하나의 함수 안에 직접 결합돼 있습니다. 인덱스 저장 구조도 없어서 IndexScan 후보는 만들 수 없습니다.
