행을 당겨올까,
밀어올까?

실행 연산자 사이에서 데이터가 흐르는 방향을 정하는 두 가지 방식입니다.

Pull: 위에서 아래로 요청

앞 수업의 iterator 방식입니다. 결과를 원하는 상위 연산자가 자식에게 “다음 행 줘”라고 요청합니다.

Project.next()
  → Filter.next()
      → SeqScan.next()
      ← 행이 위로 돌아옴

결과를 필요한 만큼만 요청할 수 있고, 연산자들이 공통 인터페이스로 조립됩니다. 이 방식은 Volcano 실행 모델의 핵심 아이디어 중 하나입니다. Graefe, Volcano 논문

Push: 아래에서 위로 전달

반대로 스캔 연산자가 행을 찾으면 위쪽 연산자에 전달하고, Filter가 통과시키면 다음 연산자로 밀어 올립니다.

SeqScan: 행 발견
  ──push──→ Filter: 조건 검사
                ──통과 시 push──→ Project: 컬럼 선택
                                      ──push──→ 결과

무엇이 더 좋은가?

Pull의 장점: 필요한 만큼 결과를 요청하기 쉽고, 연산자 인터페이스를 조합하기 좋습니다.

Push의 장점: 행마다 함수 호출을 반복하는 부담을 줄이거나, 여러 행을 묶어 처리하는 벡터화 실행과 결합하기 쉽습니다.

선택: DBMS와 실행기 설계에 따라 다릅니다. 많은 엔진은 한 방식만 고집하기보다 상황에 따라 여러 실행 방식을 섞습니다.

두 모델 모두 중요한 질문은 같아요. “행을 누가 다음 연산자에 전달하며, 연산자 간 경계를 어떻게 관리하는가?”

미니 DBMS는?

현재 프로젝트는 별도 연산자 연결 구조가 없고, select_rows()의 반복문이 파일에서 행을 읽어 조건을 확인한 뒤 바로 출력합니다. 따라서 이 코드를 완전한 pull 또는 push 실행기로 부르기보다는, 하나의 함수에서 순차 처리하는 단순 실행이라고 보는 게 정확합니다.
