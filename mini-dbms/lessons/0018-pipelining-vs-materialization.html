결과를 흘려보낼까,
모아둘까?

연산자 사이의 중간 결과를 즉시 전달하는 파이프라이닝과, 먼저 저장해 두는 물질화를 비교합니다.

파이프라이닝: 만들어지는 대로 전달

Scan → Filter → Project에서 Scan이 행을 찾으면 Filter가 검사하고 Project가 필요한 컬럼을 바로 다음 단계로 넘깁니다. 전체 중간 결과를 별도 파일에 저장할 필요가 없어요.

Scan: 행 하나 생성
  → Filter: 조건 확인
    → Project: 필요한 컬럼 전달
      → 결과 출력

중간 데이터를 기록하고 다시 읽는 비용을 줄이고, 첫 결과를 빨리 내보낼 수 있습니다. 이전의 pull/push 실행 모델 모두 파이프라이닝으로 동작할 수 있어요.

물질화: 중간 결과를 저장

물질화는 어떤 연산의 결과를 먼저 메모리나 임시 파일에 저장한 뒤, 다음 연산이 그 결과를 사용하게 합니다.

Scan → Filter → 임시 결과 저장
                         ↓
                    다음 연산이 읽음

중간 결과를 다시 사용할 수 있고, 처리 단계를 나누기 쉽지만 저장 공간과 쓰기·읽기 비용이 추가됩니다.

어떤 연산은 입력을 모아야 한다

단순 필터는 행을 받자마자 통과 여부를 결정할 수 있어 스트리밍에 적합합니다. 하지만 전체 행을 정렬하려면 보통 입력을 충분히 모아 정렬한 뒤에야 첫 결과를 낼 수 있어요. 이런 연산은 파이프라인을 멈추는 지점이 될 수 있습니다. 해시 조인도 한쪽 입력으로 해시 테이블을 만든 다음 다른 쪽을 탐색하는 식으로 내부 상태를 모읍니다.

데이터베이스 교재는 물질화를 각 하위 결과를 저장해 부모 연산에서 사용하는 방식으로, 파이프라이닝은 결과가 생성되는 동안 부모가 바로 소비하는 방식으로 설명합니다. Database System Concepts, Query Processing

현재 프로젝트에서는

현재 SELECT는 행을 읽고 조건을 검사한 뒤 통과한 컬럼을 바로 출력합니다. 중간 결과 테이블이나 임시 파일을 만들지 않으므로 간단한 파이프라이닝에 가까운 흐름입니다. 다만 실행 연산자 인터페이스를 구현한 것은 아니어서, 엄밀히는 하나의 반복문 안에서 바로 처리하는 방식입니다.

큰 정렬이나 조인 기능은 현재 SQL 문법에 없으므로, 그런 중간 저장 단계는 아직 필요하지 않습니다.
