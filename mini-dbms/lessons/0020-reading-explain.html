EXPLAIN은 DBMS가 쿼리를 어떤 연산으로 실행하려 하는지 보여줍니다.

간단한 계획 예시

PostgreSQL에서 다음 쿼리를 계획한다고 가정해 봅시다.

SELECT name FROM people WHERE age >= 18;

계획은 다음처럼 트리로 표시될 수 있어요.

Seq Scan on people
  Filter: (age >= 18)

이는 “people을 순차적으로 읽고, 각 행에 조건을 적용한다”는 뜻입니다. 계획 트리에서 하위 연산자가 입력을 만들고 위쪽 연산자가 결과를 받아 처리합니다.

추정값과 실제값 구분

일반 EXPLAIN은 실행 전에 계산한 계획과 추정 정보를 보여줍니다. 예를 들어 PostgreSQL의 rows=...는 노드가 내보낼 것으로 예상한 행 수이고, cost=시작..전체는 내부 비용 단위의 추정치입니다. 이 비용 숫자는 초나 밀리초가 아닙니다. [공식 EXPLAIN 안내](https://www.postgresql.org/docs/18/using-explain.html)

EXPLAIN ANALYZE는 계획뿐 아니라 쿼리를 실제 실행한 뒤 실제 행 수와 시간도 보여줍니다. 그래서 추정 행 수와 실제 행 수가 크게 다른지 확인할 수 있어요. 단, ANALYZE 옵션은 실제 쿼리를 실행하므로 쓰기 쿼리에서는 데이터 변경에 주의해야 합니다. [EXPLAIN ANALYZE 옵션](https://www.postgresql.org/docs/18/sql-explain.html)

읽을 때 먼저 볼 것

1. 어떤 스캔인가? Seq Scan인지 Index Scan인지 본다.

2. 필터와 정렬이 어디 있나? Filter, Sort 같은 작업을 찾는다.

3. 행 수 추정은 현실적인가? EXPLAIN ANALYZE라면 estimated rows와 actual rows를 비교한다.

비용은 여러 계획을 비교하는 추정치고, 실제 성능 진단에서는 실제 행 수, 실행 시간, 읽은 페이지 등도 함께 봅니다.

미니 DBMS에는 아직 없음

이 프로젝트는 별도 계획 트리나 비용 추정기가 없으므로 EXPLAIN 기능도 없습니다. 다만 현재 SELECT의 동작을 개념적으로 적으면 SeqScan → Filter → Project라고 설명할 수 있어요.
