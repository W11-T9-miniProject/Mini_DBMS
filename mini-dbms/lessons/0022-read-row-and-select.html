저장된 바이트가
결과 행이 되기까지

INSERT에서 만든 직렬화 형식을 db_read()가 되돌리고, SELECT가 조건을 적용하는 과정을 따라갑니다.

행 파일에는 값이 차례로 기록됨

앞 수업에서 db_append()는 각 값의 길이를 4바이트로 기록하고, 뒤이어 값의 바이트를 저장했습니다.

[len][id bytes][len][name bytes][len][age bytes]
  1      "7"     4      "Mina"    2      "24"

각 행은 스키마의 컬럼 순서대로 저장되므로, 읽는 쪽도 같은 스키마 순서를 알아야 합니다.

db_read()가 한 행을 복원

select_rows()는 .rows를 열고 db_read()를 반복 호출합니다. db_read()는 컬럼마다 길이 접두부를 읽고, 그 길이만큼 값을 메모리에 할당해 읽습니다.

db_read(file, table, &row)
  1. 값 길이 읽기
  2. 길이만큼 바이트 읽기
  3. 문자열 끝 표시 추가
  4. INTEGER 형식 등 데이터 검증
  5. DbRow 반환

파일 끝에 정상 도달하면 0, 행을 읽으면 1, 데이터가 잘못되었거나 읽기 오류면 -1을 반환합니다.

SELECT가 행을 처리

select_rows()
  ├─ db_read() → DbRow
  ├─ matches() → WHERE에 맞나?
  ├─ projection[] → 어떤 컬럼을 출력하나?
  └─ write_field() → CSV 형태로 출력

matches()는 정수 컬럼은 숫자로 비교하고 텍스트 컬럼은 문자열 비교를 합니다. 조건을 통과한 행만 요청된 컬럼 순서대로 출력합니다.

오류가 나면?

길이가 최대 텍스트 길이보다 크거나, 값이 파일 끝까지 다 들어오지 않았거나, 정수 값이 유효하지 않으면 db_read()는 손상되었거나 읽을 수 없는 데이터로 보고 오류를 반환합니다. 다만 이 검사는 형식 오류를 발견하는 것이고, 누락된 WAL이나 백업처럼 복구하는 기능은 아닙니다.

테이블이 없고 데이터 파일도 아직 없으면 현재 SELECT는 빈 결과로 취급합니다. 파일은 있는데 중간 레코드가 잘려 있으면 읽기 오류가 납니다.
