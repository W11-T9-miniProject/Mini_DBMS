테이블 하나의 구조와, 데이터베이스가 모든 객체의 구조를 기록하는 장부를 구분해 봅니다.

스키마: 테이블의 설계

이 프로젝트의 people.schema는 테이블 컬럼과 타입을 적어 둡니다.

id INTEGER
name TEXT
age INTEGER

이 정보가 있어야 프로그램은 각 행에 어떤 값이 몇 개 있고, 정수와 문자를 어떻게 검사할지 알 수 있어요.

카탈로그: 데이터베이스 객체의 장부

시스템 카탈로그는 DBMS가 관리하는 메타데이터 저장소입니다. 테이블뿐 아니라 인덱스, 뷰 같은 객체와 그 정의를 기록할 수 있습니다.

SQLite는 데이터베이스 파일 안에 sqlite_schema라는 특별한 테이블을 두고 테이블·인덱스·뷰·트리거 등의 정의를 기록합니다. CREATE TABLE 같은 명령을 실행하면 SQLite가 이 장부를 갱신합니다. SQLite Schema Table 문서

그러면 people.schema도 카탈로그인가?

메타데이터를 저장한다는 넓은 의미에서는 카탈로그 역할의 일부를 합니다. 앞서 “카탈로그가 없다”고만 말한 건 너무 단순화한 설명이었어요.

정확한 차이는 관리 방식입니다. 현재는 사람이 테이블마다 .schema 파일을 준비하고, db_table_open()이 필요한 파일을 직접 읽습니다. SQLite 같은 DBMS는 내부 카탈로그를 DBMS가 직접 관리하고 SQL의 DDL 명령으로 갱신합니다.

현재 프로젝트:
사람이 people.schema 작성 → DBMS 코드가 파일을 읽음

일반 DBMS:
CREATE TABLE 실행 → DBMS가 카탈로그에 구조 기록
                → 이후 쿼리가 카탈로그에서 구조 확인

CREATE와 ALTER가 생기면?

CREATE TABLE은 테이블 정의를 카탈로그에 등록하고 데이터 저장 공간을 준비하는 명령이 됩니다. ALTER TABLE은 카탈로그의 정의를 바꾸며, 변경 종류에 따라 기존 행을 어떻게 해석하거나 변환할지도 처리해야 합니다.

현재 파일 구조를 유지하는 간단한 구현이라면 CREATE가 .schema를 만들고 ALTER가 이를 수정할 수 있습니다. 다만 기존 .rows의 컬럼 순서·값 형식과 새 스키마가 맞도록 보장해야 합니다.
