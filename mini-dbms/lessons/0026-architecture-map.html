실제 DBMS의 주요 역할을 현재 프로젝트의 함수·파일과 연결해 지금까지의 흐름을 정리합니다.

실제 DBMS의 개념적 흐름

SQL
 ↓
파서 → AST → 이름/타입 검증
 ↓
논리 계획 → 최적화 → 물리 실행 계획
 ↓
실행기 연산자 (SeqScan / IndexScan / Filter / Project ...)
 ↓
저장 계층 (페이지 캐시 / B+트리 / 인덱스 / 트랜잭션 로그)
 ↓
데이터 파일

실제 제품마다 계층 이름과 경계는 다르지만, 역할을 나눠 보면 SQL 의미를 해석하고, 실행 방법을 선택하고, 데이터를 안전하게 읽고 쓰는 큰 흐름이 보입니다. SQLite 아키텍처

현재 프로젝트에서의 대응

SQL 파일 ── main()                         [구현]
             ↓
db_execute() / next() / insert() / select_rows() [구현]
             ↓
WHERE Expr + matches()                     [구현]
             ↓
select_rows()의 파일 반복문                 [순차 스캔]
             ↓
db_read() / db_append()                    [구현]
             ↓
.schema / .rows 파일                        [저장 형식]

db_table_open()은 사람이 준비한 `.schema` 파일을 읽어 테이블 정의를 메모리에 올립니다. db_read()는 `.rows`의 길이 접두부 형식에서 행을 복원하고, db_append()는 새 행을 직렬화해 덧붙입니다.

개념은 배웠지만 아직 없는 코드

SELECT 전체 AST, 독립된 논리 계획과 물리 계획

비용 추정과 통계 테이블, EXPLAIN 출력

B+트리 인덱스와 페이지 캐시

시스템 카탈로그를 DBMS가 관리하는 CREATE/ALTER

WAL/롤백 저널 기반 복구와 동시성 제어

독립된 실행 연산자(iterator, push, vectorized execution)

이 항목들은 앞에서 실제 DBMS의 개념으로 살펴봤지만, 현재 미니 DBMS에 구현된 기능은 아닙니다.
