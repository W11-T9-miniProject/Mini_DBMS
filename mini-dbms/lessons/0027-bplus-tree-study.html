CMU 강의 노트 · 강의 슬라이드

구현에 필요한 최소 그림

내부 노드: 어떤 자식으로 내려갈지 결정하는 경계 키
리프 노드: 정렬된 ID와 행 파일 위치를 보관
리프 링크: 다음 키 범위를 순서대로 방문할 때 사용

lookup(id): 루트 → 내부 노드 → 리프 → 행 위치
insert(id, offset): 리프에 정렬 삽입 → 가득 차면 분할
                                     ↘ 경계 키를 부모에 삽입

이 과제는 우선 ID 동등 검색을 사용하지만, 연결된 리프 구조는 B+트리의 핵심 특징이며 범위 검색으로 확장할 때 도움이 됩니다.

영상 보며 답해 보기

  1. 내부 노드의 키가 실제 레코드 위치를 담나요, 아니면 탐색 경계를 정하나요?
  2. 모든 ID가 최종적으로 어느 노드에 저장되나요?
  3. 리프가 꽉 찼을 때 키를 잃지 않고 어떻게 나누나요?
  4. 부모에 올라가는 분리 키는 검색 경계를 어떻게 유지하나요?

구현 후에는 이 질문을 실제 코드의 노드 필드와 분할 함수에 연결해 확인하면 됩니다.

과제와 연결

B+트리 key: signed INTEGER ID
B+트리 value: .rows 안의 행 시작 byte offset

SELECT ... WHERE id = N
  → B+트리에서 offset 검색
  → storage가 해당 offset에서 행 읽기
  → 선택 컬럼 출력

메모리 인덱스는 프로세스 종료 후 사라집니다. 다음 실행에서 기존 .rows 데이터도 ID 인덱스로 찾으려면 시작 시 파일을 스캔해 트리를 다시 만들어야 합니다.
